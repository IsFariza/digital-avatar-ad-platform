# User Interface Wireframes and Prototype

## 1. Introduction

This document describes the preliminary user interface design for the Digital Avatar Platform for Advertising Video Production and Campaign Personalization.

The purpose of the interface is to make advertising content creation clear, editable and easy to review.

The current wireframes are static design materials with fictional data.

They do not represent a fully working application.

## 2. Design Objectives

The interface should help users:

1. Create an advertising campaign.
2. Enter campaign information.
3. Review generated content.
4. Edit advertising scripts.
5. Prepare campaign variants.
6. Approve content.
7. Request video generation.
8. Check progress and review results.

## 3. Screen 1: Campaign Brief

The first screen allows users to enter basic campaign information.

Main fields:
- Product name
- Campaign objective
- Target audience
- Language or market
- Communication tone
- Output format

The screen also includes a draft preview area.

A proposed action allows users to request a sample advertising draft.

The design explains that generated content must be reviewed and edited before approval.

## 4. Screen 2: Draft Review

The second screen presents generated advertising materials.

The proposed interface separates:

### Advertising Copy
Text used in the advertising message.

### Visual Concept
A written explanation of the intended video appearance.

### Avatar Video Script
Text intended for the digital avatar presenter.

Users should be able to edit content before approving it.

## 5. Campaign Variants

The interface includes the concept of campaign versions.

A user may prepare different messages for:
- Different audiences
- Different languages
- Different campaign contexts

Each variant should remain connected to the original campaign.

## 6. Content Approval

The review screen includes an approval step.

Planned controls:
- Save draft
- Approve script
- Request video generation

If approved content is edited, new approval should be required.

The interface should show that artificial intelligence was used to prepare the draft.

## 7. Screen 3: Generation Progress

The generation status screen illustrates several possible states.

### Processing
The video generation task is active.

### Completed
The generated result is available for review.

### Failed
The system displays an understandable error message.

### Needs Attention
The system cannot confirm whether the provider accepted the request.

In uncertain cases, the user should check the status before starting another generation attempt.

## 8. Result Review

After generation, the user should be able to:

- Preview the result
- Compare it with the approved script
- Review content quality
- Identify the selected campaign version
- Retrieve the approved result

Automatic publication is not included.

## 9. Interaction Scenarios

### Scenario 1: Create Draft
The user enters campaign details.

The proposed system validates the fields and prepares an editable draft.

### Scenario 2: Create Variant
The user selects an audience or language and creates a new version.

The system should preserve the original campaign context.

### Scenario 3: Generate Video
The user approves the script and selects generation settings.

The system should submit the request and display its status.

## 12. Conclusion

The wireframes provide an initial representation of the platform workflow.

The design focuses on editable content, user approval, clear progress information and recovery from generation problems.
